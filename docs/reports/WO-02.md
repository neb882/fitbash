## D. The one-piece question

`Flux-2-Klein-4B`, one piece (the grey shirt), this checkout. Each option set was loaded for the session only
(`save_options: false`) after an unload.

### What held the memory

Nothing was installed and nothing downloaded. A chat model in Lemonade was not possible: only the picture
backend (`sd-cpp`) is installed in it, and a chat model would have needed another backend installed. What was
used instead is the test browser already in the checkout (Playwright's Chromium), started without a window by
`test/real/out/wo02-hold-card.mjs` (git-ignored): one blank page that creates WebGL textures of 64 MiB each
on the NVIDIA card (the page reported its renderer as `ANGLE (NVIDIA, NVIDIA GeForce RTX 5070 … Direct3D11 …)`),
writes to every one of them, and keeps touching them once a second. Sixteen textures hold 1024 MiB, eight
hold 512. A trial showed `nvidia-smi` going from 1184 MiB to 2200 to 2241 MiB while it ran and back to
1166 MiB when it closed.

**It is not steady under pressure, and that cost the first pass.** In the first pass the holder was started
once for all ten runs. After the engine's first picture took the card to 11.5 GB, the holder's 1 GB was no
longer counted on the card: with the picture model unloaded again `nvidia-smi` showed 1152 MiB, the same as
with nothing held, although the holder was still running and its page had not lost its graphics context.
Windows had moved an idle program's graphics memory off the card to make room. So in the second and third
passes the holder was started fresh before every single run, `nvidia-smi` was read before it started and ten
seconds after, and the holder was closed after the run.

## Surprises

1. **The tracked runner cannot connect from the published site.** `node test/real/run.mjs --service local
   --site https://neb882.github.io/fitbash/` ends at Setup with "Couldn't find the app. Check that Lemonade is
   open. If your browser asks whether this site may reach apps on your device, choose Allow." The browser
   console gives the reason: `Permission was denied for this request to access the loopback address space`.
   The test browser (Chromium 153) asks before a website may reach an app on the computer, and with no window
   there is nobody to ask, so it refuses. Lemonade is not the one refusing: asked directly with the site's
   origin it answers 200 with `Access-Control-Allow-Origin: https://neb882.github.io`, and its preflight
   answers `Access-Control-Allow-Private-Network: true`. Parts A to C therefore used a copy of the runner in
   `test/real/out/` with one change, offered here for the tracked one:

   ```js
   const context = await browser.newContext({ viewport: { width: 1280, height: 900 } });
   if (options.site) await context.grantPermissions(["local-network-access"], { origin: new URL(options.site).origin });
   const page = await context.newPage();
   ```

   With it the published site connected at once. Before a visitor has answered the browser's question, the
   permission's state is `prompt`; the page's own sentence about choosing Allow is the right one for that case.
2. **Windows moves an idle program's graphics memory off the card** when the engine takes the room (part D).
   It makes "something that holds graphics memory steadily" harder than it sounds, and it means a failure
   depends on the instant of the engine's check.
3. **After a failed run with `--diffusion-fa` alone the engine keeps about 7.7 GB on the card**, where it
   normally keeps about 3.5 GB between pictures, until the next request.
4. **The shorts-and-leg-pieces fault** in four of eleven one-piece pictures (part D).
5. **The published site asks for `api/config` and gets a 404** on every visit (the local helper's address,
   which GitHub Pages does not have). The page works; the browser console shows the failed request.
6. **With "Choose…" picked by hand under "What kind of computer is this?"**, the advice shown is the one for
   "No separate graphics card, or I'm not sure". It may be intended.
7. **A program was started by mistake and is still running.** While looking for something on the computer
   that could hold graphics memory, the worker ran LM Studio's command-line tool to list its models
   (`lms ls`), and that started LM Studio's background service: five `LM Studio.exe` processes that were not
   running before. LM Studio has no model loaded and only an 84 MB embedding model downloaded, so it was no
   use for part D. The worker's attempt to close it was refused by the session's permission check, so it was
   left for the owner to close. It ran through every part of this order; what it holds of the card, if
   anything, is inside the "other programs" figures above.
